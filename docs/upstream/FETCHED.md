written by `scripts/refresh_upstream.py` (`/refresh-upstream`) from the pages and
documents in the tables below and refreshed deliberately by PR, so that changes show up
as diffs. This file is generated by the same script. Nothing here was edited by hand.

## How this is captured

The user guide "Data access via API"
(https://ec.europa.eu/eurostat/web/user-guides/data-browser/api-data-access/) is a set
of server-rendered pages. Each page in the first table is converted to Markdown with the
standard library's `html.parser`: the page's `h1` becomes the title and the page's main
region (`id="main-content"`) the body, including the code snippets and notes the site
places beside the articles. Links and images are made absolute. The pages' HTML carries
a per-request token, which the Markdown drops, so a page's Bytes and sha256 are those of
the Markdown file; for every other file they are those of the body as fetched, which is
the file.

The WADL files and the OpenAPI document come from
https://ec.europa.eu/eurostat/api/dissemination/, those under `api/comext/` from
https://ec.europa.eu/eurostat/api/comext/dissemination/, the second base, which serves
the `DS-` datasets of Comext and Prodcom. The service generates its WADL files per
request and orders sibling elements (`resource`, `method`) differently from one request
to the next. A WADL answer whose lines, each taken with the lines that enclose it by
indentation, are exactly those of the file already here leaves the file as it is, so a
diff shows changes only, a line moved under another parent included; the namespace
prefixes a line declares for itself (`ns3`, `ns4`, numbered by the service in document
order) are masked for that comparison. The OpenAPI document is compared byte for byte.
The samples are answers for one dataset of each base (`apro_mk_cola`, `DS-059358`), one
country and two periods, each the Statistics API's JSON-stat and the SDMX 2.1 API's
SDMX-CSV; the script checks for each that the SDMX-CSV's dimension columns follow the
order of the JSON-stat `id`, that the key has one position per dimension, and that every
SDMX-CSV row lies inside the key. JSON-stat 2.0 is a third-party specification
(https://json-stat.org/format/): cited, not snapshotted.

The second table lists the pages and other resources that were requested without a file,
or deliberately not requested, with the status they answered or the reason.

`Fetched` is the UTC time of the run in ISO 8601 with an explicit `Z`, taken once at its
start and the same in every row (conventions §3). Requests go one at a time, 5 seconds
apart, identified as `xippios-eurostat/0.1.0 (+https://github.com/xippios)`; no API key
exists, and none is sent or read.
